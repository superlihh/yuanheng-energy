# 阿里云上线采购与部署清单

## 结论

当前项目适合先用一台 Linux 云服务器完成演示和小范围试点，不需要购买 GPU 服务器，也不建议现在就购买 RDS、Redis 或负载均衡。

项目当前由 Java 网关、Python 计算服务、前端静态文件和 SQLite 组成。将服务部署在同一台 ECS 上即可运行：Nginx 对外提供 80/443，Java 监听本机 8080，Python 监听本机 8001，SQLite 只允许本机访问。

这套配置适合比赛演示、内部试用和少量企业账号。它不能直接等同于多企业生产系统；正式商用前需要把 SQLite 迁移到 MySQL 或 PostgreSQL，并增加异地备份、监控和故障恢复演练。

## 学生券怎么用

1. 使用长期保留的阿里云个人账号完成实名认证和学生认证。
2. 在阿里云高校用云支持计划页面领取学生抵扣金。
3. 进入学生用券专区，先查看订单中的“可抵扣金额”和“适用商品”，再下单。
4. 不要先充值或购买不确定能使用代金券的产品；支付页面没有显示抵扣时不要确认订单。

阿里云官方说明显示，学生认证期间每年可领取一张 300 元抵扣金，抵扣金自领取之日起有效一年。同一身份证号或手机号每年限领一张，适用产品以学生用券专区和下单页面为准，部分产品不能与其他活动叠加。官方页面同时提供学生 ECS 低价套餐，具体规格和可用地域以购买页面为准。

## 第一阶段：低成本上线配置

建议购买一台 ECS，配置按下表选择：

| 项目 | 建议值 | 说明 |
| --- | --- | --- |
| 实例 | 经济型或通用算力型 ECS | 优先选择学生专区可抵扣的规格 |
| CPU/内存 | 2 vCPU、4 GiB 内存 | Java、Python 和 SciPy 同机运行的最低稳妥配置 |
| 系统盘 | 40--80 GiB ESSD Entry | 保存程序、数据库、日志和少量上传文件 |
| 系统 | Ubuntu 22.04/24.04 LTS x86_64 | 便于安装 JDK 21、Python 3.11、Nginx |
| 公网带宽 | 3--5 Mbps 固定带宽 | 演示和小范围试用足够；不要只按峰值带宽估算 |
| 公网 IP | 1 个 IPv4 | 绑定域名和远程维护使用 |
| 地域 | 华北、华东或离企业较近的大陆地域 | 与企业数据源、模型服务地域尽量靠近 |

2 vCPU、2 GiB 内存的学生机可以用于静态演示，但运行 Python 预测、SciPy 优化和多个登录用户时余量较小。若学生套餐只有 2 GiB，可以先用它做验证，正式试点改为 4 GiB，不要在 2 GiB 上承诺长期稳定运行。

## 还需要买什么

### 必买或建议购买

- **域名**：只在需要企业从公网访问、启用 HTTPS、发送正式链接时购买。内部演示可以暂时使用 IP。
- **备份**：至少配置 ECS 自动快照；数据库文件和导出报告再同步到同地域 OSS。服务器损坏、误删或升级失败时，不能只依赖服务器本地文件。
- **模型调用额度**：AI 问询使用模型 API，不需要 GPU。可以使用阿里云百炼的 OpenAI 兼容接口，单独创建 API Key，并给账号设置费用告警和调用限额。

### 暂时不要买

- **GPU ECS**：本项目当前调用外部模型服务，不在服务器本地训练大模型。
- **Redis**：现有版本没有把会话和任务队列放进 Redis，购买后不会自动提高可靠性。
- **RDS**：当前代码使用 SQLite。迁移代码、表结构和备份策略完成前，RDS 不会被应用使用。
- **负载均衡 SLB/ALB**：只有两台及以上应用服务器或需要高可用时才有意义。

## 第二阶段：企业正式试点配置

当出现多个企业、多人同时使用、需要长期留存账单和审批记录时，再升级为：

1. ECS 4 vCPU、8 GiB 起步，应用服务与数据库分开部署。
2. RDS MySQL 8.0 或 PostgreSQL，使用内网访问，不开放公网数据库端口。
3. OSS 保存原始导入文件、报告、快照和审计归档。
4. CloudMonitor 设置 CPU、内存、磁盘、接口错误率、数据库连接数和费用告警。
5. 两台 ECS 或备份实例完成恢复演练后，再考虑负载均衡和自动扩容。

数据库迁移完成前，系统只能按单机 SQLite 模式运行；不要把同一个 SQLite 文件放在多个应用实例之间共享。

## 上线安全检查

1. 安全组公网只开放 TCP 80 和 443。
2. SSH 22 端口只允许固定办公 IP 或 VPN 网段访问，不要设置为 `0.0.0.0/0`。
3. 8080、8001、3306、6379 等服务端口只监听内网或 `127.0.0.1`，不对公网开放。
4. 使用普通运维账号和 SSH 密钥登录，禁止长期使用 root 密码登录。
5. API Key 只放在服务器环境变量或密钥管理中，不写入前端、Git、报告和截图。
6. 每天备份数据库，至少保留 7 个历史版本；每月实际下载一次备份并验证能恢复。
7. 上线前用测试账号检查注册、登录、权限隔离、审批、数据导入、备份恢复和 AI 失败时的本地解释。
8. AI 只能解释计算结果，不能批准方案、申报交易或控制生产设备；现场设备保持只读接入，直到企业完成单独的安全验收。

## AI 接入建议

当前项目已经使用 OpenAI 兼容的 Responses 接口。若改用阿里云百炼，保留后端适配方式，只替换服务器环境变量中的 API Key、Base URL 和模型名。百炼官方文档提供了 OpenAI 兼容接口和 Responses API，Base URL 需要使用与业务空间和地域对应的地址；不要把别人的代理地址或个人密钥写进项目默认配置。

建议先用一个轻量的通用模型完成策略问询和报告整理，再根据实际问询量调整模型。所有价格、金额、节省额和约束判断必须由本项目的计算服务生成，模型只负责解释和整理文字。

## 采购后的实施顺序

1. 领取学生券并在支付页面确认抵扣成功。
2. 创建 ECS、绑定弹性公网 IP、设置安全组和 SSH 密钥。
3. 安装 JDK 21、Python 3.11、Nginx，上传项目并创建 systemd 服务。
4. 配置域名和 HTTPS，确认外部只能访问 Nginx 代理地址。
5. 配置 `POWER_DB_PATH`、`OPENAI_API_KEY`、`OPENAI_BASE_URL` 和 `OPENAI_MODEL`，密钥不写入仓库。
6. 导入一批合成数据，完成注册、审批、方案计算、报告导出和设备只读遥测测试。
7. 配置自动快照和 OSS 备份，做一次完整恢复演练后再给企业使用。

## 费用判断

300 元抵扣金足以覆盖一次低配 ECS 或部分云产品费用，但不能保证长期免费，也不能覆盖模型调用、域名、超出流量、快照、OSS 和数据库的所有费用。真正下单前以阿里云订单页的“应付金额、抵扣金额、续费价格和到期规则”为准。

本项目第一阶段的合理目标是：先用一台 2 vCPU/4 GiB ECS 完成可访问的试点环境，保留原 SQLite；确认企业数据、审批流程和计算结果都稳定后，再投入 RDS 和多机高可用费用。
